### 中断与恢复（2026-11-20 13:xx）

前两次 `web-frontend` 构建均在 `yarn run build` 的 Nitro 打包阶段被内核 OOM 杀掉
（`/tmp/cc-ccbuild.log`，12:34 / 13:04 各一次）。原因是 `package.json` 的 build 脚本
硬编码 `NODE_OPTIONS=--max-old-space-size=8192`，覆盖了 Dockerfile 里的 4096，
在 8 GB 内存机器上把宿主内存与 swap 一起吃满，进而触发全局 OOM。

**关键发现：sourcemap 是内存主因**

`web-frontend/config/nuxt.config.prod.ts` 原本对 `server` 与 `client` 都强制生成
sourcemap。部署中没有配置 `SENTRY_AUTH_TOKEN`，这些 map 既不会上传也没有用途，
却让 Nitro 打包阶段内存翻倍：8192 堆 + 12 GB swap 仍陷入 swap 抖动
（40 多分钟无日志、进程长期处于 `D` 状态、CPU 时间几乎不增长）。

处理方式：sourcemap 改为由 `NUXT_BUILD_SOURCEMAP=true` 显式开启，默认关闭；
Dockerfile 堆上限回到 4096。

**本轮恢复采取的预防措施：**

1. `web-frontend/config/nuxt.config.prod.ts`：sourcemap 默认关闭（见上）。
2. `web-frontend/Dockerfile` 新增 `NODE_MAX_OLD_SPACE_MB` 构建参数（默认 4096），
   通过 `NODE_OPTIONS` 注入；4 GB 堆在关闭 sourcemap 后足够。
3. `web-frontend/package.json` 的 build 脚本改为 `${NODE_OPTIONS:-...}`，
   使 Dockerfile 的堆设置生效（原先硬编码 8192 会覆盖）。
4. 构建前临时新增 swap：`/www/swapfile2`、`/www/swapfile3` 各 4 GB，
   总 swap 达 12 GB，作为峰值缓冲。
5. 构建前 `docker builder prune -af` 清理 16.6 GB 构建缓存
   （清理前 `/www` 仅剩 6.1 GB，构建会写满磁盘）。
6. 构建以 `setsid nohup nice` 脱离会话后台执行，日志写 `/tmp/cc-frontend-build.log`，
   会话中断不会连带杀死构建。
7. 构建期间不改前端源码、不并行构建；后台 monitor 每 30 秒采样内存与进度。
8. 用 `oom_score_adj=-500` 保护当前 agent 进程，避免被 OOM 选中。

### 首次上线失败与修复（2026-11-20 15:07）

部署本地镜像后后端进入崩溃循环：

```
SystemCheckError: (translation.E002) You have provided an invalid language
code in the LANGUAGES setting: 'zh_Hans'.
```

第 1 轮把 `LANGUAGES` 写成 `zh_Hans`，但 Django 的语言代码必须用连字符，
`zh_Hans` 只是 `.po`/`.mo` 的目录名（`django.utils.translation.to_locale` 负责映射）。

修复：

- 后端 `LANGUAGES` 改为 `("zh-hans", "简体中文")`。
- 前端 `config/locales.js` 的 locale code 同步改为 `zh-hans`（数据文件名仍是 `zh_Hans.json`）。
- `LangSwitcherDropdown` 会把该 code 提交给后端 `language_validation`，两端必须一致。
- 后端测试 `test_user_views.py` 中的 `zh_Hans` 一并改为 `zh-hans`。
- 附带修复：`modules/core/moment.js` 仍只注册已删除语言的 locale，
  改为 `zh-cn`（moment 的中文文件名），并在 i18n 插件中把 `zh-hans` 映射到 `zh-cn`，
  否则中文界面日期会回退英文。

### 风险与回滚方式

- 前端构建内存占用高（8 GB 机器，构建时 swap 吃紧），失败时先清理 Docker builder 缓存再重试。
- 镜像标签一旦切换，回滚方式是 `.env` 改回 `develop-latest` 后 `docker compose up -d`。
- 0142 迁移只做 `completed_onboarding` 置真与字段默认值调整，可安全回滚（`noop` 反向）。
- 新增 swap 文件可随时 `swapoff /www/swapfile2 && rm /www/swapfile2` 回收。
