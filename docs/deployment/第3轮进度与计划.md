## 0. 用户要求与执行原则

- 彻底汉化：切换简体中文后无残留英文，译文贴合办公语境、非生硬机翻；用户点名项（`Height/Small/Medium/Large`，`Group`、`You have not yet created any groupings`、`Group rows together by a field.`、`choose a field to group by`，`All items`、`Dashboard`、`Automation`、`Create`、`Members`、`Settings` 等）及**所有同类问题**全覆盖，并主动发现未点名问题。
- 全能力解锁：仪表盘 bar/line/pie/doughnut 图表；分享“隐藏 logo / 允许导出”；颜色调整；看板/日历/时间线；日期依赖；To personal；审计日志、数据扫描器等**全部已实现但受限能力**解除前后端限制；若代码不存在则评估并制定/执行实现计划（流程与风格与现有一致，参考成熟产品）。
- 去品牌/去非工具化：左下角“sometable”不抢眼，侧栏折叠不出现错误“S”（保留原 baserow icon 或折叠不显示）；模态窗口等处不滥用标志；清理宣传/引导/营销弹窗等非工具属性；视觉克制，工具定位办公。
- 范围：点名仅为举例，**所有同类型问题**均需修复并主动排查。
- 过程：每步计划与进度写入文档；服务器内存/swap/硬盘受控，避免崩溃。
- 交付约束（本轮新增）：**每次代码变更后直接部署上线供用户检查**（用户不查代码）；**代码更新后同步到 GitHub**。

## 2. 环境与阻塞（影响“立即部署”）

- 资源：`/www` 可用约 18G，`/` 约 5.3G；内存 7.8G，swap 4G（已用约 2G）。历史多次 OOM，构建必须单次、限堆、后台脱离并监控，必要时临时 swap 且事后清理。
- Docker：`docker`/`docker-compose` 命令存在，但 `/var/run/docker.sock` 对当前用户不可写（`srw-rw---- root docker`，当前用户 `dev/uid=1000` 不在 `docker` 组，`sudo -n docker` 不可用）。因此**当前无法直接执行镜像构建与容器滚动更新**。
- Node/构建工具：`node v20.19.0`、`yarn 1.22.22`、`uv` 可用，`just` 无；仓库无 `node_modules`（前端全量本机构建不可直接进行且高风险），常规上线路径为 Docker 构建。
- 部署位置：本会话环境未发现 `/www/baserow2`；线上运行拓扑/compose 位置待确认（无法 `docker ps`）。

**对“每次代码变更后部署上线”的执行策略**：`sudo -n docker` / `sudo -n docker compose` 在本环境可用，线上栈为当前目录 compose 项目 `sometable-*`（`BASEROW_VERSION=local-20261120-1548`，caddy+db+redis+backend+celery*+web-frontend 均在运行）。因此每个代码变更批次将：改码→校验→提交→推送 GitHub（远程 `git@github-sometable:...`，若 SSH 别名/凭据不可用则记录失败与手工命令）→**受控构建并部署上线**供检查。
- 构建方式：使用 `docker-compose.yml` + `docker-compose.build.yml`，设置新 `BASEROW_VERSION` 标签（如 `local-YYYYMMDD-r3bN`），`NODE_MAX_OLD_SPACE_MB=4096`，sourcemap 默认关闭；后台脱离（`setsid nohup`+日志）并监控 `free -h`/swap/`df -h`，避免并行重任务；构建后更新 `.env` 并 `docker compose up -d` 滚动重启相关服务，验证健康状态与关键页面/API。
- 为控资源与时长，细粒度修复会合并为“可验收”的批次后再构建部署（每批必部署+必推送），而非每个字符改动都触发一次完整构建。
