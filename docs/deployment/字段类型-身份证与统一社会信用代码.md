# 身份证号与统一社会信用代码字段

> 适用：`sometable.com` 生产环境。新增于 `local-20261121-r3b17`。

## 为什么不能直接用「单行文本」约束

Baserow 的「单行文本」字段只有默认值、最大长度等选项，没有正则表达式或校验和校验入口；2.4 的字段约束（FieldConstraint）只实现了「非空唯一」这类数据库约束，不能配置格式。因此仅靠配置单行文本无法保证录入的是合法身份证号或统一社会信用代码。

## 新增字段类型

在表的「新建字段」下拉中可选择：

| 类型 | 说明 | 校验规则 |
| --- | --- | --- |
| 身份证号 | 中国大陆居民身份证号码 | 18 位，前 17 位数字，校验位为数字或 X/x；校验出生日期；按 GB 11643 校验码校验 |
| 统一社会信用代码 | 企业/机构统一社会信用代码 | 18 位，字符集为 `0123456789ABCDEFGHJKLMNPQRTUWXY`；按 GB 32100 校验码校验 |

两者均为定长 18 字符，前端录入时即时校验，后端在**创建行、更新行、导入、upsert** 时再次校验；校验失败会返回明确错误，不会写入非法值。大小写不敏感，身份证末尾的 `x` 会自动按 `X` 处理。

## 兼容能力

- 可用于筛选（包含/开头是等）、排序、分组、聚合、唯一约束（非空）；
- 可被公式字段引用；
- 支持 CSV/Excel 导入与 API 写入；
- 字段转换（从文本转成新类型）时只做格式正则过滤，历史数据中的**校验和错误值不会自动清空**，请在转换后检查并修正。

## 实现位置

- 后端校验与生成：`backend/src/baserow/contrib/database/fields/chinese_validators.py`
- 字段类型：`backend/src/baserow/contrib/database/fields/field_types.py`（`IdCardFieldType`、`UnifiedSocialCreditCodeFieldType`）
- 前端校验：`web-frontend/modules/core/utils/string.js`（与后端保持同步）
- 前端字段类型：`web-frontend/modules/database/fieldTypes.js`
- 迁移：`backend/src/baserow/contrib/database/migrations/0231_chinese_identity_fields.py`

> 前端与后端校验规则必须保持一致；修改任一处时请同步修改另一处及其单元测试。
